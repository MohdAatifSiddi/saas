# Documentation cross-check findings

- NestJS Helmet documentation: Helmet sets security-related headers and should be registered before other middleware or setup that calls `app.use()`. Source: https://docs.nestjs.com/security/helmet
- NestJS CORS documentation: `app.enableCors()` accepts a strict configuration object or callback; the supplied API should not use broad origins when credentials are enabled. Source: https://docs.nestjs.com/security/cors
- NestJS validation documentation: use a global `ValidationPipe`; relevant hardening options include `transform`, `whitelist`, `forbidNonWhitelisted`, `forbidUnknownValues`, `disableErrorMessages`, and not exposing validation targets/values. Source: https://docs.nestjs.com/techniques/validation
- Better Auth NestJS documentation: the community Nest integration requires `bodyParser: false`, mounts Better Auth through its module, and registers an authentication guard globally by default. Source: https://better-auth.com/docs/integrations/nestjs
- Better Auth Express documentation: use `fromNodeHeaders(req.headers)` when calling `auth.api.getSession`; do not run `express.json()` before the Better Auth handler. Source: https://better-auth.com/docs/integrations/express
- Better Auth options documentation: configure an explicit `baseURL`; configure exact `trustedOrigins`; production `secret` must be present; email-password options include reset-token expiry and session revocation settings. Source: https://better-auth.com/docs/reference/options
- Better Auth security documentation: do not disable CSRF or origin checks; secure cookies, origin validation, session management, route-sensitive rate limits, trusted proxy handling, and secret rotation are supported. Source: https://better-auth.com/docs/reference/security
- Community integration README: its option for disabling the built-in global guard is `disableGlobalAuthGuard`; the package also exposes body-parser size options. Source: https://github.com/ThallesP/nestjs-better-auth
- Prisma PostgreSQL documentation: PostgreSQL provider and connection configuration must match the selected Prisma version and adapter strategy. Source: https://www.prisma.io/docs/orm/core-concepts/supported-databases/postgresql
